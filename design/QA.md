# QA: как доводим Storybook до уровня Figma

## Команда

```bash
npm run build-storybook && npm run qa     # отчёт: qa/out/report.md, скриншоты: qa/out/screens
npm run qa -- --only=organisms-header     # одна группа историй
npm run qa -- --update-baseline           # принять текущие скриншоты как эталон (qa/baseline)
```

В CI то же самое делает `.github/workflows/qa.yml` на каждый push и PR: отчёт появляется в Summary запуска, скриншоты лежат в артефакте `qa-report`.

## Что проверяется (каждая история × светлая и тёмная тема)

| Проверка | Уровень | Что ловит |
|---|---|---|
| История упала / пустая, ошибка JS, `console.error`, HTTP 4xx | ошибка | Сломанные истории и контролы |
| Спека Figma (`design/figma-specs.json`, допуск 1 px) | ошибка | Размеры, паддинги, gap, радиусы, шрифты |
| Тень перекрыта | ошибка | Позиционированный сосед закрывает тень (баг ScrollEdge над таб-баром) |
| Тень обрезана | ошибка / предупр. | `overflow` предка режет тень |
| Текст вылез | ошибка | Длинные подписи вылезают из блока |
| За краем экрана | ошибка | Элемент шире экрана 393 и не в скролле |
| Зона нажатия | ошибка < 24, предупр. < 40 | Мелкие кнопки. В нативе расширять hit-area до 44 pt (iOS) и 48 dp (Android) |
| axe-core | critical — ошибка, остальное — предупр. | Кнопки без названия, вложенные кнопки, контраст |
| Скриншот против `qa/baseline` | ошибка > 0,1 % пикселей | Регрессии после рефакторинга |

## Цикл (1 итерация ≈ 1 день)

1. **Аудит.** `npm run qa`, а также сверка с Figma: `get_design_context` и скриншоты компонентов со страницы Design System 2.0.
2. **Разбор.** Каждая находка — баг кода, неточность спеки или решение дизайна. Решения дизайна (контраст, размер зон нажатия) выносятся дизайнеру, код их не меняет.
3. **Пачка правок.** Сначала общие причины (layout, токены), потом частные.
4. **Повторный прогон.** 0 ошибок — иначе обратно к шагу 3.
5. **Ревью глазами.** Скриншоты светлой и тёмной темы рядом с Figma.
6. **Эталон.** `--update-baseline`, после этого любое изменение пикселей = осознанное.

## Критерии «почти идеально»

- 0 ошибок в `npm run qa`, 100 % спек Figma в пределах 1 px.
- Все компоненты из `src/docs/registry.ts` покрыты спекой (сейчас 47 замеров).
- 0 нарушений axe уровня serious и выше, контраст AA для текста (решение по токенам — ниже).
- Скриншоты стабильны: разница с эталоном < 0,1 %.
- Нативная проверка: те же экраны на iPhone 15 и Pixel 8 (шрифты, safe area, Dynamic Type / font scale 1.3).

## Решено по контрасту (итерация 1)

- `text-secondary` → `#6E6E6E` (4,85 : 1 на белом, 4,53 : 1 на `#F7F7F7`).
- `danger` (заливка) → `#CC291B`: белый текст бейджа 5,4 : 1. `text-danger` в тёмной теме — `#FF6B5C`.
- Тёмная тема: `accent` → `#4B4BFF` (белый текст 5,6 : 1), `text-accent` → `#8A8AFF`.
- В Figma текст отделён от заливок: `ui-colors/blue-text`, `ui-colors/red-text`.
- Кнопки больше не сжимаются по высоте во flex-колонке (`fullWidth` делит место только в рядах).

Осталось на решение: строки `list-item` 24 px и кнопки S 32 px — в нативе расширять зону нажатия, не меняя вид.
